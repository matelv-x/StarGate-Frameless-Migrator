STAR GATE / FRAMELESS — WSPÓLNY INSTALATOR MIGRACYJNY

Uruchom StarGate-Frameless-Migrator.exe z folderu Pobrane lub innego folderu poza starą instalacją.
Zamknij StarGateWebView / Framelesswindow i ich launchery przed migracją.

1. Program wykrywa instalacje na podstawie starych plików launcher.json oraz katalogów StarGate/Frameless w głównym katalogu dysku systemowego i LocalAppData\Programs.
2. Jeżeli masz oba programy, wybierz w liście ten, który chcesz zaktualizować. Jedno uruchomienie aktualizuje jeden wybrany program. Jeśli folder nie zostanie wykryty, wskaż go przyciskiem.
3. Pobierany jest najnowszy opublikowany instalator z właściwego repozytorium matelv-x na GitHubie. Program sprawdza nazwę aplikacji, architekturę, rozmiar oraz SHA-256 względem manifestu wydania. Żadne poświadczenia nie są zaszyte w pliku EXE.
4. Pliki JSON z zapisanymi adresami i profilami są kopiowane do LocalAppData\StarGate-Frameless-Migration\[data-identyfikator]\settings. Oryginały nie są usuwane. Stary pojedynczy adres Frameless jest importowany do Profiles, bez zastępowania istniejącego profilu.
5. Cały rozpoznany stary katalog jest PRZENOSZONY obok, z końcówką .legacy-[data-identyfikator]. Ten wariant NIE KASUJE starej wersji. Pozwala odzyskać także nietypowe pliki, które mogły się znajdować w starym katalogu.
6. Otwiera się standardowy kreator nowej wersji. Wybierz nowy, pusty katalog; nie wybieraj katalogu .legacy-… ani innego istniejącego programu. Przejdź przez kreator. Jeśli kreator czeka na zamknięcie otwartej aplikacji, zamknij ją, aby migrator mógł zakończyć kontrolę.
7. Po instalacji migrator sprawdza identyfikator pakietu i SHA-256 DLL aplikacji oraz zachowanie zapisanych adresów. Istniejące skróty pulpitu i autostartu wskazujące na wybraną starą wersję są kierowane na nową aplikację; przed zmianą powstają kopie skrótów.

PRZERWANIE / ODZYSKIWANIE
Po anulowaniu lub błędzie instalacji migrator próbuje przywrócić stary katalog, jeśli jego pierwotna ścieżka jest wolna. Nie nadpisuje nowego katalogu. Plik recovery.json w katalogu sesji zapisuje stare i nowe lokalizacje oraz kopię konfiguracji launchera. Nie usuwaj katalogu .legacy-… ani katalogu sesji, dopóki nie sprawdzisz nowej wersji.
Przy awarii zasilania można przenieść katalog .legacy-… z powrotem do ścieżki OldRoot opisanej w recovery.json, pod warunkiem że ścieżka jest wolna. Kopie oryginalnych plików ustawień są w settings.

DOSTĘP I UPRAWNIENIA
Framelesswindow jest repozytorium prywatnym. Wymaga dostępu do konta matelv-x przez Git Credential Manager. Samo zalogowanie w przeglądarce może nie wystarczyć. Program nie pyta o hasło i nie zapisuje tokenu.
Uruchamiaj migrator jako ten sam użytkownik Windows, który korzystał ze starego programu. Jeśli Windows odmówi przeniesienia katalogu na C:\, migracja zatrzyma się; wymagane mogą być uprawnienia administratora tego samego konta. Nie używaj innego konta administratora, bo ma inne LocalAppData.
Gotowy plik jest dla Windows x64 (samowystarczalny .NET). Na Windows ARM64 wymaga emulacji x64 i instaluje obecne wydanie x64 z GitHuba; nie jest to natywny instalator ARM64.

ZWERYFIKOWANO
Testy na sztucznych katalogach: rozpoznawanie obu programów i niestandardowych lokalizacji, odrzucanie katalogów projektów oraz wspólnych katalogów obu aplikacji, kopia adresów, import najstarszych formatów Frameless, zachowanie istniejących profili, odrzucanie błędnego pakietu oraz ograniczenia adresów pobierania.
Sprawdzono odczyt aktualnych manifestów GitHub obu aplikacji, w tym autoryzację prywatnego repozytorium. Nie wykonywano migracji rzeczywistej instalacji użytkownika ani pełnego testu instalacji nowej wersji.

KOD I KOMPILACJA
Archiwum migration-source.zip zawiera pełny kod, projekt i testy. Kompilacja:
dotnet publish Migration.csproj -c Release -r win-x64 --self-contained true -p:DebugType=None -p:DebugSymbols=false
Testy (bez migracji): StarGate-Frameless-Migrator.exe --self-test
Sprawdzenie wydań (bez instalacji): StarGate-Frameless-Migrator.exe --check-releases
